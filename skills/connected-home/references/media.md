# Work with music, speakers and TVs

Find the intended speaker/TV or media library with endpoint_query. Inspect the exact endpointId; copy declared command and route IDs. Search music and list/get playlists through control with waitForResult:true when the command returns correlated results. Use the returned media identifiers instead of inventing IDs or treating an output event as a command.

Echo Dot Max/Alexa speakers can be typed VOICE_ASSISTANT and declare media-player and speaker commands. Search names and capabilities before saying Alexa control is unavailable. Check relevant authorized account labels (for example home devices versus iCloud) and retain the account that returned each target. For "this song" without a referent, ask title/artist/link without a blanket capability denial. A declared search-and-play command may accept a song query directly; use its exact documented payload fields rather than inventing a media URI or requiring a separate music library when this route supports direct search.

For pause or lower-volume requests, discover active playback/current speaker volume on matching connected devices; ask which target if several or none can be established. An explicit relative-volume amount is needed unless the device declares a suitable step command with a defined/default amount. Read supported units and payload before sending. Keep playback and volume on the intended provider route.

"Manage my playlist" may mean read, play, curate or edit. Discover media-playlist operations on relevant authorized connections, then ask which playlist and desired change. list-playlists/get-playlist support browsing. Spotify library routes can declare create-playlist, add-to-playlist, remove-from-playlist, rename-playlist and unfollow-playlist. Creation makes a private playlist; tracks must be exact returned Spotify track IDs (up to 100 per call). For removal, Spotify requires trackIndex:-1 and trackUri copied from the listing; this removes all occurrences, so make that scope clear and do not use it for a request to remove only one duplicate. Rename changes the selected owned playlist's name and verifies it by reading back. Unfollow removes the selected playlist from this account's library; it does not permanently delete the provider playlist. Re-list to confirm absence. A playlist-mutation-result acknowledges the provider snapshot; verify requested contents by reading them. applied:false means a partial operation, such as successful creation with unconfirmed initial tracks: preserve the returned playlistId and inspect before another write. Existing connections may need reconnecting to grant playlist-modify-private/public and user-library-modify; a 403 must not be reported as a successful edit. Never repeat an uncertain write automatically. Reordering and permanent playlist deletion are not exposed by this adapter. Other providers may differ; inspect concrete route commands.

Playback, pause and volume use the documented payload fields supported by the chosen provider route. Verify afterward with endpoint_query, declared speaker/media-player/connectivity expansion and forceDeviceAttributeQuery:true. Dispatch acceptance alone does not confirm audible playback. A paused TV is not necessarily powered off. Report stale/unavailable state as unknown and never automatically repeat an accepted state-changing command.
