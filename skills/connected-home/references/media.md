# Work with music, speakers and TVs

Find the intended speaker/TV or media library with endpoint_query. Inspect the exact endpointId; copy declared command IDs; Port OS selects provider routes. Search music and list/get playlists when the command returns correlated results: REST sets top-level `responseType: "SYNC"` beside `target` and `message`; MCP sets `waitForResult: true` on control. Each message body accepts only its own declared fields (`search-media` has no `provider`). Use the returned media identifiers instead of inventing IDs or treating an output event as a command.

A SUCCEEDED media-player command (play-media, play, pause, seek) means the command was delivered, not that the app now plays it: an app can sit on a profile picker, sign-in or error screen. Confirm with `endpoint_query` (`expand` the media-player capability, `forceDeviceAttributeQuery: true`), or, when the endpoint declares `snapshot`, send `snapshot/get-snapshot` with `{"responseFormat":"BASE64"}` and look at the image. Without `responseFormat` the snapshot comes back as a signed URL you cannot view. A play-media refused as TARGET_UNSUPPORTED means the route does not support that media's provider or resource kind; the error lists what it supports, so search for or pick a supported media ID. MESSAGE_UNSUPPORTED means the route does not advertise the command itself.

Echo Dot Max/Alexa speakers can be typed VOICE_ASSISTANT and declare media-player and speaker commands. Search names and capabilities before saying Alexa control is unavailable. Check relevant authorized account labels (for example home devices versus iCloud) and retain the account that returned each target. For "this song" without a referent, ask title/artist/link without a blanket capability denial. A declared search-and-play command may accept a song query directly; use its exact documented payload fields rather than inventing a media URI or requiring a separate music library when this route supports direct search.

For pause or lower-volume requests, discover active playback/current speaker volume on matching connected devices; ask which target if several or none can be established. An explicit relative-volume amount is needed unless the device declares a suitable step command with a defined/default amount. Read supported units and payload before sending. Keep playback and volume on the intended logical target.

now-playing.active means this provider session has content on the target; it can remain true while paused. Use playback-state, not active, to decide whether it is playing. A false active value on Spotify says nothing about a separate Sonos-native session.

transfer-playback with {} moves only the connected provider account's session; a Spotify track on native Sonos does not establish that it is the same Spotify Connect session. Read fresh source/destination state first. For a requested manual handoff, check destination play-media and seek declarations, capture the source's exact media ID and position, play that ID, then seek with {"positionMilliseconds":<captured milliseconds>} (convert seconds × 1000). Verify destination media, position and playback before pausing the source. Explain unavailable seek/media identity and queue loss instead of silently restarting and claiming a complete transfer.

## File audio and TV apps

play-uri takes {"uri":"<HTTPS audio file URL>"}; it does not download or transcode the file in Port OS. Inspect the selected route's source kinds and formats. Sonos audio clips accept MP3 or WAV, not Ogg; other Sonos streaming paths have different format support. Provider pages and catalog IDs belong in the declared search/play-media workflow, not in a clip URL. play-audio instead takes {"audio":{"data":"<base64 bytes>","mimeType":"audio/wav"}} with a MIME type and duration allowed by that route. Do not submit an Ogg file as WAV or assume a filename proves its contents. An accepted clip is scheduled, not confirmed audible; clip-status may be event-only and cannot be forced into a current reading.

For "launch Netflix" or another TV app, inspect content-launcher/search-and-play as well as application-launcher (see Control a TV below). Use only a declared command and its exact payload. A TV exposing neither app launch nor the requested keypad key cannot perform it through Port OS; do not invent HOME/directional-key payloads or select a different TV.

For "set up a playlist of songs and play it on my Sonos", build an active playback queue unless the customer also asks to save a reusable library playlist. Discover the Spotify library and the logical target's capabilities. Search the library's declared `media-search/search-media` with `{"query":"<artist or mood>","type":"track"}` and `waitForResult:true`; the payload type is lowercase, even if capability configuration lists `TRACK`. Copy returned canonical playable track IDs. Use a logical speaker or native group declaring `media-queue`; Port OS selects a compatible provider. Check `supportedMediaResources` and `maxItemsPerPlay`. Send one `play-queue` with `{"mediaIds":["<returned track ID>","<returned track ID>"]}` to the exact selected logical target. Do not save a library playlist or simulate a queue with repeated single-track commands for this request.

Read `get-queue` with `{}` and `waitForResult:true` on the same logical target, and verify fresh media-player observations. The result separates `currentMediaId` from upcoming `mediaIds`; `complete:false` is a provider-limited window. To append without restarting, use `add-to-queue` with `{"mediaId":"<returned track ID>"}` once per track. When `requiresQueueVersion:true`, first read the queue and include its exact `queueVersion` in that append payload, then read again after each append. `play-queue` has no `queueVersion` field. Spotify Connect does not accept a queue version. A conflict or uncertain write requires inspection rather than automatic replay or replacement. Native queues expire 24 hours after creation; append does not extend expiry.

A failed search does not prove that the speaker stopped or the whole connection is unavailable. Preserve current playback, report the failed operation, and use fresh device observations for playback claims. Do not substitute remembered song names or invented IDs for returned playable tracks. For tools-only clients without bundled references or a resource reader, the advertised `control` description includes the live-queue recipe; do not assume a `resources/read` bridge exists.

"Manage my playlist" may mean read, play, curate or edit. Discover media-playlist operations on relevant authorized connections, then ask which playlist and desired change. list-playlists/get-playlist support browsing. Spotify library routes can declare create-playlist, add-to-playlist, remove-from-playlist, rename-playlist and unfollow-playlist. Creation makes a private playlist; tracks must be exact returned Spotify track IDs (up to 100 per call). For removal, Spotify requires trackIndex:-1 and trackUri copied from the listing; this removes all occurrences, so make that scope clear and do not use it for a request to remove only one duplicate. Rename changes the selected owned playlist's name and verifies it by reading back. Unfollow removes the selected playlist from this account's library; it does not permanently delete the provider playlist. Re-list to confirm absence. A playlist-mutation-result acknowledges the provider snapshot; verify requested contents by reading them. applied:false means a partial operation, such as successful creation with unconfirmed initial tracks: preserve the returned playlistId and inspect before another write. Existing connections may need reconnecting to grant playlist-modify-private/public and user-library-modify; a 403 must not be reported as a successful edit. Never repeat an uncertain write automatically. Reordering and permanent playlist deletion are not exposed by this adapter. Other providers may differ; inspect concrete route commands.

Playback, pause and volume use the documented payload fields declared by the chosen logical target. Verify afterward with endpoint_query, declared speaker/media-player/connectivity expansion and forceDeviceAttributeQuery:true. Dispatch acceptance alone does not confirm audible playback. A paused TV is not necessarily powered off. Report STALE state as the last known state with its sampledAt, errored or missing state as unknown, and never automatically repeat an accepted state-changing command.

## Control a TV

A TV (type TELEVISION) carries its own recipe in the endpoint description; read it first. Its messages, `supportedKeys` and `supportedMediaResources` say exactly what it can do.

1. **See what is on.** `endpoint_query` with the TV's `endpointId`, `expand: ["media-player"]` and `forceDeviceAttributeQuery: true`. `playbackState` is PLAYING, PAUSED or STOPPED; `nowPlaying` names the app (`appId`), the title, `provider` and `positionMs`. `appId` `com.google.android.apps.mediashell` means someone is casting to the TV: transport, seek and app launches act on their session, so ask before taking it over.
2. **Find something to play.** The TV has no search of its own, so search the connected library: `media-search/search-media` on the YouTube or Spotify endpoint with `{"query":"<what was asked>","maxResults":5}` and `waitForResult: true`. Copy a returned `mediaId` exactly. Check it against the TV's `supportedMediaResources` (for example YouTube video, channel and playlist; Spotify track, album, artist, playlist, show and episode).
3. **Play it.** `media-player/play-media` on the TV with `{"mediaId":"<returned ID>"}`. The TV opens the provider's app on that media. A YouTube playlist made with the library's `media-playlist/create-playlist` plays the same way, with its returned `m/youtube/video/playlist/<id>`.
4. **Confirm it, every time.** Other commands are only acknowledged, but after `play-media` or `launch-application` check once before saying it plays: SUCCEEDED means the TV received the command, and the app can still stop on a profile picker without reporting anything. Read now-playing again as in step 1, or send `snapshot/get-snapshot` with `{"responseFormat":"BASE64"}` and `waitForResult: true` and look at the screen. Without `responseFormat` the snapshot is a signed URL you cannot view. YouTube can stop on its "Who's watching?" screen: tell the person, and send `keypad-input/send-key` `{"keyCode":"SELECT"}` rather than repeating `play-media`, take another snapshot, and when the picker is still there and the TV declares `touch-input`, tap the profile.
5. **Transport.** `play`, `pause`, `next`, `previous` and `stop` with `{}` act on whichever app holds the media session. `seek` `{"positionMilliseconds":90000}` jumps to a position; `skip-forward` and `skip-backward` `{"deltaPositionMilliseconds":10000}` move from the current one (the distance is required); `start-over` `{}` goes back to the beginning. Seeking works only when the playing app allows it, so read `positionMs` afterwards.
6. **Volume.** `speaker/set-volume` `{"volume":20}` (0 to 100), `speaker/adjust-volume` `{"volumeDelta":-5}` after reading the current `volume`, and `speaker/set-mute` `{"mute":true}`.
7. **Open an app.** Read the `application-list` attribute (`expand: ["application-launcher"]`, `forceDeviceAttributeQuery: true`). It lists Android package names only, so match the name asked for: Netflix `com.netflix.ninja`, YouTube `com.google.android.youtube.tv`, Spotify `com.spotify.tv.android`, Disney+ `com.disney.disneyplus`, Prime Video `com.amazon.amazonvideo.livingroom`, Hulu `com.hulu.livingroomplus`. Send `application-launcher/launch-application` `{"catalogVendorId":0,"applicationId":"<package>"}` and confirm with a snapshot; a package the TV cannot open fails only on the TV.
8. **Move around the screen.** `keypad-input/send-key` takes only the keys in the route's `supportedKeys` (for example UP, DOWN, LEFT, RIGHT, SELECT, BACK, HOME, PLAY, PAUSE); a key outside them is refused. `touch-input/tap` takes `{"x":0.5,"y":0.5}` as fractions of the screen width and height; take a snapshot first to find the point and another to see the result.

Errors: TARGET_UNSUPPORTED on `play-media` means the TV cannot play that media's provider or kind, and the message lists what it can; MESSAGE_UNSUPPORTED means the TV does not declare that message at all. Neither sent anything. Never repeat an accepted command to "make sure"; read the state instead.
