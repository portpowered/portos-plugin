# Work with music, speakers and TVs

Find the intended speaker/TV or media library with endpoint_query. Inspect the exact endpointId; copy declared command IDs; Port OS selects provider routes. Search music and list/get playlists when the command returns correlated results: REST sets top-level `responseType: "SYNC"` beside `target` and `message`; MCP sets `waitForResult: true` on control. Each message body accepts only its own declared fields (`search-media` has no `provider`). Use the returned media identifiers instead of inventing IDs or treating an output event as a command.

Echo Dot Max/Alexa speakers can be typed VOICE_ASSISTANT and declare media-player and speaker commands. Search names and capabilities before saying Alexa control is unavailable. Check relevant authorized account labels (for example home devices versus iCloud) and retain the account that returned each target. For "this song" without a referent, ask title/artist/link without a blanket capability denial. A declared search-and-play command may accept a song query directly; use its exact documented payload fields rather than inventing a media URI or requiring a separate music library when this route supports direct search.

For pause or lower-volume requests, discover active playback/current speaker volume on matching connected devices; ask which target if several or none can be established. An explicit relative-volume amount is needed unless the device declares a suitable step command with a defined/default amount. Read supported units and payload before sending. Keep playback and volume on the intended logical target.

For "set up a playlist of songs and play it on my Sonos", build an active playback queue unless the customer also asks to save a reusable library playlist. Discover the Spotify library and the logical target's capabilities. Search the library's declared `media-search/search-media` with `{"query":"<artist or mood>","type":"track"}` and `waitForResult:true`; the payload type is lowercase, even if capability configuration lists `TRACK`. Copy returned canonical playable track IDs. Use a logical speaker or native group declaring `media-queue`; Port OS selects a compatible provider. Check `supportedMediaResources` and `maxItemsPerPlay`. Send one `play-queue` with `{"mediaIds":["<returned track ID>","<returned track ID>"]}` to the exact selected logical target. Do not save a library playlist or simulate a queue with repeated single-track commands for this request.

Read `get-queue` with `{}` and `waitForResult:true` on the same logical target, and verify fresh media-player observations. The result separates `currentMediaId` from upcoming `mediaIds`; `complete:false` is a provider-limited window. To append without restarting, use `add-to-queue` with `{"mediaId":"<returned track ID>"}` once per track. When `requiresQueueVersion:true`, first read the queue and include its exact `queueVersion` in that append payload, then read again after each append. `play-queue` has no `queueVersion` field. Spotify Connect does not accept a queue version. A conflict or uncertain write requires inspection rather than automatic replay or replacement. Native queues expire 24 hours after creation; append does not extend expiry.

A failed search does not prove that the speaker stopped or the whole connection is unavailable. Preserve current playback, report the failed operation, and use fresh device observations for playback claims. Do not substitute remembered song names or invented IDs for returned playable tracks. For tools-only clients without bundled references or a resource reader, the advertised `control` description includes the live-queue recipe; do not assume a `resources/read` bridge exists.

"Manage my playlist" may mean read, play, curate or edit. Discover media-playlist operations on relevant authorized connections, then ask which playlist and desired change. list-playlists/get-playlist support browsing. Spotify library routes can declare create-playlist, add-to-playlist, remove-from-playlist, rename-playlist and unfollow-playlist. Creation makes a private playlist; tracks must be exact returned Spotify track IDs (up to 100 per call). For removal, Spotify requires trackIndex:-1 and trackUri copied from the listing; this removes all occurrences, so make that scope clear and do not use it for a request to remove only one duplicate. Rename changes the selected owned playlist's name and verifies it by reading back. Unfollow removes the selected playlist from this account's library; it does not permanently delete the provider playlist. Re-list to confirm absence. A playlist-mutation-result acknowledges the provider snapshot; verify requested contents by reading them. applied:false means a partial operation, such as successful creation with unconfirmed initial tracks: preserve the returned playlistId and inspect before another write. Existing connections may need reconnecting to grant playlist-modify-private/public and user-library-modify; a 403 must not be reported as a successful edit. Never repeat an uncertain write automatically. Reordering and permanent playlist deletion are not exposed by this adapter. Other providers may differ; inspect concrete route commands.

Playback, pause and volume use the documented payload fields declared by the chosen logical target. Verify afterward with endpoint_query, declared speaker/media-player/connectivity expansion and forceDeviceAttributeQuery:true. Dispatch acceptance alone does not confirm audible playback. A paused TV is not necessarily powered off. Report STALE state as the last known state with its sampledAt, errored or missing state as unknown, and never automatically repeat an accepted state-changing command.
