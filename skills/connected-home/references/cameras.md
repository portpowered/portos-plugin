# Look at a kitchen camera or check a room

"What's going on in my kitchen" can mean room-device state or camera activity. Discover kitchen endpoints and group membership with endpoint_query/group_query, checking relevant authorized accounts when the first lacks a match. Search snapshot capability and camera provider/channel aliases when a literal Kitchen name is absent. A camera's room association establishes the target; unrelated Ring/Swann channels are not proof that a kitchen camera was found. Ask the user which camera/channel if identity remains ambiguous.

For a camera that declares snapshot/get-snapshot, call control with its copied full id and get-snapshot message ID, payload {}, and waitForResult=true. Inspect the returned image pixels before describing what is visible, and report timeOfSample and uncertainty. A snapshot is not a live feed or proof that an event is occurring now. If permission, connection, provider or image retrieval fails, report the limitation without inventing a scene. Do not infer occupancy from lights or a device name.

For device-state questions, force a read of only declared attributes such as connectivity, power or media-player. Stale, missing or unavailable data cannot establish current activity. If only historical values are returned, label them historical and say current state is unknown. Never send household controls merely to observe a room.

For "record 30 seconds" or a snapshot from an RTC-only camera, a live-video command alone does not save an artifact. The Port OS website's live viewer provides Take snapshot and Record 30 seconds, followed by Download snapshot or Download video. Start the stream and wait for actual video frames before capturing. The clip uses remote video only, stays in browser memory until downloaded, and has a 32 MiB limit. Interrupted, empty or oversized recordings are discarded. Stop the stream when finished. These browser controls are distinct from the control snapshot command; do not send undeclared recording commands or claim the MCP API saved a clip. A failed capture does not justify substituting an unrelated camera.

Roborock cameras declare authorization-requirements separately from RTC. Query the declared requirement's configuration status if camera authorization is missing. The customer sets the pattern once in the website's Saved camera pattern settings; the server stores it encrypted and supplies it automatically to permitted snapshots and video. Never request the pattern in chat or put it in an RTC payload. A saved pattern is not proof that the vendor accepted it; report a failed camera request accurately.

For "explore my house", "drive toward the kitchen" or "draw my floor plan", use the robot's declared remote-control unary-move operation, not named-room cleaning, and follow the rooms guide's start/move/end checklist. Establish advancing live video before remote driving and inspect the resulting view after each short bounded movement. Fresh snapshots may supplement that feedback; lack of a snapshot capability does not block working live video. Stop when frames or movement outcomes are unavailable, or when the view cannot establish a clear route. End remote control before using the declared return-to-dock command. Maintain a rough visual sketch with uncertainty; images alone do not establish measured distances. Never claim physical exploration or a completed map from a proposed movement sequence.
