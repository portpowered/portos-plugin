# Thermostat and current indoor temperature

For "lower the temperature" or "what's the temperature right now?", determine whether the user means indoor/device temperature or outdoor weather. If context does not decide, ask which; do not silently substitute weather for a connected-home reading.

1. Read-only discovery: endpoint_query for thermostats and temperature-sensor capabilities, with focused room/name queries and pagination. If the host exposes multiple authorized accounts, inspect likely home-device connections before declaring a sensor absent. Keep each account's IDs separate. Ask which room/device if several match.
2. Current temperature means the temperature-sensor ambient reading, not a thermostat setpoint. Read the exact endpoint with declared temperature-sensor/connectivity expansion and forceDeviceAttributeQuery:true. Report a FRESH value and units as current. A STALE value is the last known temperature: report it with its sampledAt, not as live. Errored or missing readings are unknown. Do not infer a temperature from mode, a target or weather.
3. For control, read the exact endpointId and copy the route and declared thermostat command. Clarify desired target or relative amount and units when missing. `thermostat/set-target-temperature` takes `{"targetSetpoint":{"value":21,"scale":"CELSIUS"}}` (or `lowerSetpoint` and `upperSetpoint` for a range thermostat): `scale` is exactly `CELSIUS` or `FAHRENHEIT`, not C/F, and `value` is a number in that scale; copy the exact field names from the declared command. A relative change uses a FRESH current setpoint, not ambient temperature; if unavailable, ask for an explicit target. Use the documented payload fields; the backend validates the request.
4. Send once and verify fresh observations: read the exact endpoint with forceDeviceAttributeQuery:true, expanding both the thermostat and its temperature-sensor, so the card can show the room temperature next to the setpoint. A changed setpoint does not mean the room has already cooled. Accepted dispatch without FRESH verification is unconfirmed; never automatically repeat the change. Then call endpoint_show with the thermostat's exact endpointId so the customer sees the new setpoint.

To show a thermostat so a specific card leads, call endpoint_show with the exact endpointId and primary set to one of its cardIds: "turn the thermostat fan on" uses primary:"fan" (then send the declared fan command with control), "how open are the blinds" uses primary:"closure". Without primary the device's usual card leads; every other card stays behind the details toggle.
